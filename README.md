# 管脉 · 油气管道泄漏检测智能平台

用于课程展示的可交互前端原型，包含动态封面、管线拓扑、实时曲线、告警核查、处置工单和历史分析。数据由固定种子模拟生成；没有连接真实采集设备、检测模型或后台服务。

## 本地启动

需要 Node.js 20.19+ 或 22.12+。

```sh
npm install
npm run dev -- --port 5174
```

打开 http://127.0.0.1:5174/ 。如果该端口已占用，请以终端打印的地址为准。

```sh
npm test        # 业务闭环、离线状态、存储与历史统计
npm run build  # TypeScript 检查与生产构建，输出 dist/
```

## 建议演示顺序

1. 封面展示管道流动效果，点击业务流程步骤讲解核查与处置逻辑，然后进入工作台。
2. 在“疑似泄漏”场景选择示例管线 A，从值班待办进入异常核查。
3. 打开 `AL-20261014-001`，检查疑似区间、触发规则与压力／流量证据；“打开实时监测”可定位异常窗口，“返回实时窗口”恢复实时视图。
4. 填写核查说明并确认异常，创建关联工单并指定负责人。
5. 在工单中开始处理、填写现场结果、提交复核。可以演示退回补充记录，再复核通过。
6. 检查关联告警同步关闭，返回总览查看待办变化，在历史分析中查询和导出 CSV。

另有设备离线与正常运行场景。场景切换和重置需确认，会清除本轮操作。压力预警可以填写原因后判定误报，原始证据和操作记录仍保留。

## 页面与统计说明

| 地址 | 用途 |
| --- | --- |
| `/` | 动态封面与业务流程介绍 |
| `/overview` | 当前管线总览、值班待办、拓扑与设备 |
| `/monitor?sensor=B-M02` | 直接定位某个监测点，自动同步所属管线 |
| `/alerts` | 告警查询、排序与导出 |
| `/alerts/AL-20261014-001` | 告警诊断与人工核查 |
| `/works` | 按当前管线和状态筛选处置工单 |
| `/history` | 日期查询、分布统计、处理耗时与导出 |

- 告警数量按发现日期统计；关闭工单和平均处理耗时按关闭日期统计，均遵循管线及事件关键词筛选。处理耗时为工单创建至复核通过的时长。
- 历史趋势覆盖完整查询范围；较长范围自动合并为最多 14 个时间段，确保趋势总数与列表一致。
- 演示时钟从 2026-10-14 的固定时刻开始，按单调时钟推进，每 250 ms 更新一次，可以暂停。日期快捷按钮以模拟时钟为准。
- 操作保存在当前浏览器的 `localStorage` 中，刷新后保留；不同浏览器不共享。值班员、负责人、复核员用于流程展示，并未实现登录权限控制。
- 中文与数字字体均随项目本地提供，运行时不依赖外部字体服务；许可证保存在 `public/fonts/`。
- 总览与实时监测以 250 ms（4 Hz）刷新三项检测指标；主读数直接显示最新原始采样，保留采样精度，不插值、不预测。显示最近 60 秒波形和最近采样记录。实时监测默认查看近 5 分钟，可切换到 1、15、30、60 分钟；暂停后数值、曲线和采样记录一起冻结。
- 工作台页面及图表按需加载；支持手机侧栏和“减少动态效果”系统偏好。

## 浏览器回归

`scripts/audit-ui.mjs` 使用独立的无界面 Edge 会话，不会修改日常演示浏览器的存储。需要可用的 Playwright 模块与本机 Edge，先启动上述开发服务，再运行：

```powershell
# PLAYWRIGHT_MODULE 可指向已有 Playwright 模块目录；已能正常解析模块时可省略。
$env:PLAYWRIGHT_MODULE='你的 Playwright 模块目录'
node scripts/audit-ui.mjs
```

测试涵盖管线筛选、浏览器后退、监测点跳转、证据窗口、完整工单闭环、退回复核、刷新恢复、历史查询、CSV 下载以及 390px 手机布局。检查截图输出到 `artifacts/`。如服务地址不同，可设置 `TEST_URL`。


## 低延迟展示

采样调度使用 `performance.now()` 的单调时间计算目标采样序号，补偿定时器晚触发产生的累积漂移。一次浏览器刷新只提交最新已到期的模拟采样，卡顿后不逐条回放过时画面；暂停后停止调度，继续或重置时重新建立时间基准。该策略只用于实时画面，不代表可以丢弃未来真实告警检测或原始归档所需的数据。

数值直接显示采样值，实时曲线不执行数值补间和平滑拟合。同步本地存储退出高频刷新路径：业务编辑立即保存，时钟每 5 秒及离开页面时保存。最近一分钟曲线保留 250 ms 采样，较长窗口按显示密度抽样；原始读数与最近采样记录仍按 250 ms 更新。

“前端刷新耗时”从当前模拟采样计划时刻测至 React 提交后的下一次刷新帧回调，包含调度及渲染准备耗时，是前端观测值，并非真实设备到服务器的网络延迟或物理测量精度。后台标签页和忙碌设备可能受浏览器节流影响。

原理参考：[MDN requestAnimationFrame](https://developer.mozilla.org/en-US/docs/Web/API/Window/requestAnimationFrame)、[MDN performance.now](https://developer.mozilla.org/en-US/docs/Web/API/Performance/now)。

在与浏览器回归相同的 Playwright 环境中，运行 `node scripts/benchmark-telemetry.mjs` 可进行 8 秒前台测试。设置 `ENFORCE_LOW_LATENCY=1` 启用阈值断言，`BENCHMARK_LABEL` 用于区分输出报告，报告保存到 `artifacts/telemetry-benchmark-*.json`。其中数值稳定耗时以浏览器观察帧为单位，0 表示同一观察帧已精确匹配原始读数，并不代表物理链路零延迟。
